System overview

Project detail

Market-data workflow

Broker
  ↓
Authorized WebSocket URL
  ↓
Java WebSocket Client
  ↓
Binary Protobuf Message
  ↓
Generated Protobuf Java Object
  ↓
Market Data Model
  ↓
Strategy Engine

The WebSocket keeps the market-data channel open so price updates can arrive continuously. Protobuf is used as the message serialization format.

Authentication flow

User→Broker OAuth→Authorization Code→Backend Callback→Access Token

The authorization code is exchanged for credentials/tokens used by the application to interact with broker APIs. Sensitive values are never displayed in this portfolio.

Project detail

Why WebSocket vs REST

WebSocket

Best suited here for continuous inbound market updates where polling would be inefficient.

REST

Best suited for explicit request/response operations such as order actions and broker API calls.

Project detail

Protobuf vs gRPC

Protobuf is a serialization/IDL technology. gRPC is an RPC framework that commonly uses Protobuf. In this architecture, Protobuf messages can be consumed over the broker's WebSocket channel without implying that gRPC is being used.

Risk & order management

Risk

Checks whether a strategy-generated action is allowed within defined limits.

Position Manager

Tracks current exposure and position state.

Order Engine

Translates approved trading decisions into broker order requests.

Project detail

Failure handling

WebSocket disconnect

Detect connection state and recover the market-data channel safely.

Order rejection

Separate transport failure from broker-side rejection and update state accordingly.

Duplicate execution

Use identifiers and state checks to prevent accidental repeated actions.
