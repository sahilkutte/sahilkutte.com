Market-data workflow

What happens to a WebSocket message?

Broker
  ↓
Authorized WebSocket URL
  ↓
Java WebSocket Client
  ↓
Binary Protobuf Message
  ↓
Generated Protobuf Java Object
  ↓
Market Data Model
  ↓
Strategy Engine

The WebSocket keeps the market-data channel open so price updates can arrive continuously. Protobuf is the message serialization format; it does not mean gRPC is being used.

Communication choices

WebSocket, REST, Protobuf and gRPC — clearly separated

TechnologyWhat it isWhy it is used here
WebSocketPersistent communication channelContinuous inbound market-data updates
RESTHTTP request/response API styleExplicit broker operations such as order requests
ProtobufSerialization + message schemaCompact structured binary market-data messages
gRPCRPC framework, commonly using ProtobufNot required for the broker WebSocket data path

Failure handling

Important real-time failure cases

WebSocket disconnect

Detect connection state and recover the market-data channel safely.

Order rejection

Separate transport failure from broker-side rejection and update state accordingly.

Duplicate execution

Use identifiers and state checks to prevent accidental repeated actions.
